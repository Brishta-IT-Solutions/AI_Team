# Agent guidance for this repository

This repository *is* the Control Center, so its rules about agents apply here too.

## Non-negotiables

- The backend is the only authority for task state. Never add a path that writes `tasks.stage` outside `services/tasks.apply_transition`.
- Approvals are human-only. Never grant `approve.*`, `merge.execute`, `git.push.protected` or `production.execute` to an agent or service identity — `MACHINE_FORBIDDEN` in `domain/permissions.py` is a floor, not a default.
- Audit, approvals, requirement versions and acceptance criteria are append-only. Supersede with a new row; never add UPDATE/DELETE paths or relax the triggers.
- Every mutation: lock → check principal and `expected_version` → evaluate guards → mutate → `audit()` → `emit()` → one commit. Denials go through `record_denial` (separate transaction).
- Model output is untrusted. Validate with `contracts/` (unknown fields rejected) and verify claims against Git and captured process results, not the model's word.
- No secrets, real personal data or production credentials in code, fixtures or logs.

- In `apps/worker`, the worker — never the model — commits, measures diffs and runs the approved argv checks. Each tool's process receives only its own credentials (`Config.child_env`). Junior patches are never committed directly.

## Working here

- Pure rules live in `apps/api/control_api/domain/` and must stay free of I/O. Test them without a database.
- Schema changes: edit `db/models.py`, then `alembic revision --autogenerate`, then review by hand (sequences, triggers and circular FKs are not autogenerated). `alembic check` must report no drift.
- Map new behavior to an FRD requirement ID in code comments and tests (`# AT-07`, `(FR-18)`), and update `docs/TRACEABILITY.md`.
- Worker changes must keep `apps/worker/tests/test_e2e.py` passing; it runs the real API and git with stand-in CLIs in `tests/fakes/`.
- Before pushing: `make check`.
